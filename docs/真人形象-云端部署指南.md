# 真人写实形象 · 云端部署指南

> 定位：**进阶 / 选学内容**。普通学员用本地 Live2D 卡通形象已经是完整产品体验，无需看这份指南。
> 这份指南面向想进一步探索"真人口型实时驱动"的同学。

---

## 1. 为什么真人形象必须上云

### 技术原因（一句话）

真人口型驱动模型（MuseTalk、SoulX-FlashHead、LiveTalking 等）依赖 **NVIDIA CUDA 专有特性**，Apple Silicon 的 MPS 后端不支持，本地跑不动。

### 具体拆解

| 真人方案依赖的技术 | Apple Silicon 的现实 |
|---|---|
| FP8 量化（大幅压缩计算量） | MPS 不支持 FP8 |
| FlashAttention-3（注意力加速） | 只有 CUDA 有，MPS 无 |
| cuDNN fused kernel（逐帧合成加速） | NVIDIA 专属，MPS 无对应 |
| NVIDIA Docker（GPU 容器运行时） | Mac 上没有 NVIDIA Container Toolkit |

### 常见误区

- **「M4 Ultra 有 128GB 统一内存，应该装得下」** → 装得下 ≠ 算得快。真人实时驱动的瓶颈是「算力」不是「显存容量」。LiveTalking 实时靠的是 5×H800 或 RTX4090 的算力，不是显存大小。
- **「Mac issues 上有人说跑通了」** → 已调研：全部是非实时的离线视频合成（SadTalker 5 秒视频渲染 5 秒），没有实时交互案例。

### 调研来源

本结论来自 2026-06-04 双轮 13 路多智能体并行调研，核实了 GitHub issues / README / 第三方实测帖，详见 `调研材料/真人数字分身-Mac本地可行性调研.md`（仓库内）。

## 2. 推荐云端方案

### 选什么框架：LiveTalking

- **项目地址**：https://github.com/lipku/LiveTalking（原名 metahuman-stream）
- **特点**：支持 WebRTC 推流 + 实时口型驱动，支持 NeRF 数字人 / 视频数字人两种形态
- **为什么选它**：文档相对完整，有 Docker 镜像，WebRTC 推流适合接进浏览器项目

### 选什么云主机：租 RTX 4090

| 平台 | 价格参考 | 特点 |
|---|---|---|
| **Vast.ai** | RTX 4090 约 $0.31/hr（折合 ¥2.2/hr） | 价格最低，竞价市场，适合按需测试 |
| **RunPod** | RTX 4090 $0.34-0.69/hr | 稳定性稍好，适合长时间运行 |
| **AutoDL**（国内） | RTX 4090 约 ¥3.5/hr | 国内网络访问快，无需科学上网 |

**按需启停估算**：每天测试 20 小时 × ¥2.2/hr ≈ **¥44-70/天**。不用时关机，不计费。

## 3. 云端部署步骤概要

> 这是路线图，具体命令以 LiveTalking 官方文档为准（版本迭代较快，请以 README 为准）。

### Step 1：租一台 RTX 4090 云主机

**Vast.ai 操作步骤**：

1. 注册账号：https://vast.ai → 充值（支持信用卡）
2. 在 "Search" 页筛选：GPU = RTX 4090，CUDA >= 12.1，Disk >= 50GB
3. 选 Template = "PyTorch 2.x" 或 "CUDA 12.1 Base"
4. 点击 Rent → 等待实例启动（约 2-5 分钟）
5. 记下实例的 SSH 地址（`ssh root@xxx.vast.ai -p xxxxx`）

### Step 2：拉取 LiveTalking Docker 镜像

SSH 进云主机后：

```bash
# 拉取官方镜像（约 15-30 分钟，取决于网速）
docker pull lipku/LiveTalking:latest

# 或者手动 clone 仓库自行构建
git clone https://github.com/lipku/LiveTalking.git
cd LiveTalking
docker build -t livetalking .
```

### Step 3：准备数字人素材

LiveTalking 支持两种形态：

1. **视频数字人（推荐入门）**：上传一段 5-10 秒的说话视频，系统自动提取人脸，之后驱动口型
2. **NeRF 数字人（高质量）**：需要 10-20 分钟的训练视频，训练时间 2-4 小时，质量更好

入门先用视频数字人，门槛低。

```bash
# 示例：用视频数字人启动服务
docker run -it --gpus all -p 8080:8080 -p 8000:8000 \
  -v /your/video:/app/data \
  lipku/LiveTalking:latest \
  python app.py --avatar /app/data/your_video.mp4 --transport webrtc
```

### Step 4：验证服务可访问

服务默认监听 8080 端口（WebRTC 信令），8000 端口（HTTP API）。

```bash
# 测试 API 可访问
curl http://your-cloud-ip:8080/health

# 用浏览器打开 LiveTalking 自带的 demo 页
# 地址：http://your-cloud-ip:8080
```

看到数字人视频画面说明服务正常。

## 4. 接入本项目

云端 LiveTalking 服务跑起来后，按以下步骤接进小艾数字分身项目。

### Step 1：配置环境变量

编辑项目根目录的 `.env` 文件：

```bash
# 切换到真人形象 provider
AVATAR_PROVIDER=realhuman

# 填写你的云端 LiveTalking 服务地址（IP:端口）
REALHUMAN_SERVICE_URL=http://your-cloud-ip:8080
```

重启服务后，后端 `/api/avatar/config` 接口会返回 `realHumanReady: true`。

**关键接口**（LiveTalking 提供）：
- `POST /api/offer`：发送 WebRTC SDP offer，建立推流连接
- `POST /api/human`：发送待说的文字，服务端 TTS + 驱动口型
- `POST /api/interrupt`：打断当前口播

### Step 3：测试延迟

真人形象的延迟预算（云端 RTX4090 + 本地 Mac）：

| 环节 | 预计耗时 |
|---|---|
| 网络往返（Mac → Vast.ai 美国节点） | 150-250ms |
| 真人口型合成（LiveTalking RTX4090） | ~30ms/帧 @ 25fps |
| WebRTC 视频解码到屏幕 | ~50ms |
| **总端到端（对话完成 → 看到人说话）** | **约 300-500ms** |

比本地 Live2D 慢约 300ms，感知上略有延迟，但真人效果明显更好。

## 5. 成本与注意事项

### 成本控制

- **用完就停**：Vast.ai / RunPod 按小时计费，测试完记得 `Stop Instance`
- **本地先开发好再上云测**：所有逻辑用 Live2D 跑通，只在需要演示真人效果时启动云主机
- **估算**：每周测试 3 次 × 2 小时 × ¥2.5/hr ≈ **¥15/周**

### 肖像授权

如果使用真实人脸（自己或他人）：
- 用自己的脸：无版权问题，但建议录制专用授权视频
- 用他人的脸：必须获得明确授权（书面更好）
- 用虚拟数字人脸（AIGC 生成）：相对安全，无真实人肖像权问题，**推荐选这条路**

### 延迟预期

- 真人形象 ≠ 0 延迟：即使最优配置也有 300-500ms 网络延迟
- 对比 Live2D：本地 Live2D 口型延迟 < 50ms，但真人效果差很多
- 取舍：课程演示 / 情感陪伴场景，300ms 延迟用户基本感觉不到

## 6. 总结：三档方案对比

| 方案 | 效果 | 成本 | 延迟 | 适用场景 |
|---|---|---|---|---|
| **本地 Live2D**（当前默认） | 卡通 2.5D | 零 | < 50ms | 日常使用 / 课程教学 |
| **云端视频数字人**（本指南） | 真人写实 | ¥15-70/周 | 300-500ms | 演示 / 进阶探索 |
| **NeRF 定制数字人**（进阶） | 高保真真人 | 高（训练 + 推理） | 类似 | 产品化 / 商业场景 |

**结论**：课程用本地 Live2D 做 MVP 完全够用。真人形象是选学内容，有兴趣的同学按这份指南去探索。
