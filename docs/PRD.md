## 1. 产品概述

### 1.1 一句话定义

一个浏览器里的**写实美女数字人对话 demo**：用户输入文字或语音 → 数字人用「龙婉」女声温柔回应 → **脸部实时对口型**说出来。所有能力（脑/声/脸/形象）都接阿里百炼，一个 `DASHSCOPE_API_KEY` 跑通。

### 1.2 背景

- 用户（讲师）此前已有城北 `digital-twin`（卡通 Live2D 形象，Mac 本地实时）。现希望做一个**真人写实**形象的版本，作为新的教学案例。
- 真人写实数字人**本地 Mac 跑不了**（依赖 NVIDIA CUDA），必须走云端。经调研，阿里云 **EMO（悦动人像 emo-v1）** 是「图+音→对口型」中**性价比最高**的方案（0.08~0.16 元/秒，每月免费 1800 秒），且与用户已锁定的 `qwen3-max`、`CosyVoice` 同生态、同一个 key。
- 详见 [调研报告](调研报告-数字人与TTS方案-2026.06.md)。

### 1.3 定位：教学案例

| 维度 | 要求 |
|---|---|
| 可讲性 | 架构 = 「脑(LLM) + 声(TTS) + 脸(数字人)」三块积木，能逐块讲给零基础学员 |
| 可复现 | 学员只需一个阿里百炼 key，`npm start` 即可跑；不碰 GPU、不碰 OSS、不翻墙 |
| 成本可控 | EMO 每月免费 1800 秒，演示基本不花钱；超出按 0.08~0.16 元/秒 |
| 可配置 | 形象、音色、性格、画幅、语速全部前端可调，方便课堂演示不同效果 |

### 1.4 设计原则

1. **一个 Key 到底**：脑/声/脸/形象/上传全走 DASHSCOPE，绝不让学员配第二套凭证。
2. **Key 不出后端**：前端永远拿不到 key，所有调用经 Express 代理。
3. **降级不阻塞**：任一环节失败（LLM 超时、视频生成失败）都有兜底，对话流程不中断。
4. **关怀岛屿视觉**：沿用既有紫色梦幻治愈设计系统，温暖、适老、好看。

## 2. 目标用户与场景

### 2.1 用户分层

| 用户 | 诉求 |
|---|---|
| **讲师（直接用户）** | 课堂上演示「真人数字人怎么做出来」，能现场改形象/音色/性格看效果 |
| **学员（学习者）** | 跟着把 demo 跑起来，理解三块积木与 API 对接 |
| **终端场景（产品想象）** | 子女为父母定制写实陪伴数字人（关怀岛屿产品愿景的真人形态） |

### 2.2 核心场景

1. **打开即聊**：进入页面，默认美女形象已就位，输入「你好」→ 数字人对口型回应。
2. **课堂换装**：讲师打开配置面板，换个形象/换个音色/把性格改成「活泼」→ 立刻演示差异。
3. **上传形象**：上传一张本地图片当数字人形象（经百炼临时存储转公网 URL）。
4. **语音对话**：按住麦克风说话 → 识别成文字 → 数字人回应。

## 4. 技术方案

### 4.1 总体架构

```
浏览器单页前端（对话 UI + 配置面板）
        │ HTTP /api/*
Express 轻后端（Key 只在这里）
   /api/chat  /api/tts  /api/figure  /api/upload  /api/avatar  /api/health
        │ Bearer DASHSCOPE_API_KEY
阿里云百炼 DashScope
   qwen3-max · cosyvoice-v2 · wanx-t2i · emo-detect-v1 · emo-v1 · 临时文件存储
```

### 4.2 一个 Key 到底

| 能力 | 模型 | 鉴权 |
|---|---|---|
| 对话 | `qwen3-max` | `Bearer $DASHSCOPE_API_KEY` |
| 语音 | `cosyvoice-v2` | 同上 |
| 形象生成 | `wanx2.1-t2i-turbo` | 同上 |
| 上传本地图 | 临时存储 `uploads?action=getPolicy` | 同上 |
| 对口型 | `emo-detect-v1` + `emo-v1` | 同上 |

### 4.3 一轮对话端到端数据流

```
用户输入（文字/语音）
 → POST /api/chat：qwen3-max 流式出文字 ──► 气泡先显示文字（秒回）
 → POST /api/tts：CosyVoice 龙婉合成 → output.audio.url（公网 mp3，24h）
 → POST /api/avatar：emo-v1(形象图URL + 音频URL + 缓存bbox) → task_id
    → 轮询 GET /tasks/{task_id} 直到 SUCCEEDED → output.video_url（对口型 mp4）
 → 前端播放视频，状态切「说话」，播完回「待机」
```

> 形象图的 `face_bbox`/`ext_bbox` 在「更换形象」时由 `emo-detect-v1` 算一次并缓存，对话每轮复用。

### 4.4 为什么选 EMO（成本对比）

| 方案 | 单价 | 每轮(5s) | 月免费 | 说明 |
|---|---|---|---|---|
| 通义万相 wan2.2-s2v | 0.5 元/秒(480P) | ~2.5 元 | 无 | 质量高但贵 6 倍 |
| **EMO emo-v1（选用）** | **0.08(1:1)、0.16(3:4) 元/秒** | **0.4~0.8 元** | **1800 秒** | 同 key、便宜、月免费 30 分钟 |

> 备选保留：EMO 偏「唱演」若表情过夸张，可同 endpoint 切回 `wan2.2-s2v`（仅换 model 名），已解耦。

### 4.5 三路视频 provider 架构（2026-06 扩展）

「图 + 音 → 对口型视频」这一层已抽成可插拔 provider（接口契约见 [providers-CONTRACT.md](providers-CONTRACT.md)），`VIDEO_PROVIDER` 三选一、设置页可热切换（内存级，不写 `.env`）：

| id | 显示名 | 凭证 | 定位 |
|---|---|---|---|
| `emo`（默认） | 阿里 EMO | `DASHSCOPE_API_KEY`（复用） | 同 Key 同生态、月免费 1800 秒，教学默认 |
| `omnihuman` | 字节 OmniHuman | `VOLC_ACCESS_KEY_ID/SECRET`（火山 V4 签名） | 即梦数字人快速模式，约 1 元/秒，口型效果对比项 |
| `seedance` | 字节 Seedance 2.0 | `ARK_API_KEY`（方舟 Bearer） | 视频大模型原生音频驱动，约 1 元/秒，带运镜/肢体表现 |

架构要点（不改变本 PRD 其余设计）：每个 provider 自包含 `configStatus / prepareFigure / generateVideo` 三个接口（`realhuman/providers/<id>.js`），互不 import、互不兜底——失败仍走既有降级（只播音频 + 静态形象）；话术库缓存按 provider 隔离；形象来源（文生图 / 上传照片）三路共用，本地源文件是唯一真相。「一个 Key 到底」原则对默认路 `emo` 继续成立，火山两路是**可选增配**，不影响学员最小复现路径。自测入口：`scripts/test-video-provider.js`。

## 5. API 对接规范

> 所有请求 `Authorization: Bearer $DASHSCOPE_API_KEY`。✅=已实测，⏳=待 M0 验证。

### 5.1 qwen3-max — 对话（OpenAI 兼容，流式）✅
- `POST https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`
- Body：`{ model:"qwen3-max", messages:[...], stream:true }`，System 注入性格 prompt

### 5.2 CosyVoice — 语音合成（返回音频 URL）✅
- `POST .../api/v1/services/aigc/multimodal-generation/generation`
- Body：`{ model:"cosyvoice-v2", input:{text,voice:"longwan_v2"}, parameters:{format:"mp3",sample_rate:24000,rate,pitch,volume} }`
- 响应 `output.audio.url`（公网 mp3，保留 24h）→ 直接喂 EMO
- 音色：`longwan_v2`(龙婉/温柔)、`longcheng_v2`(龙橙)、`longhua_v2`(龙华)

### 5.3 文生图 — 形象生成（异步）⏳
- 创建：`POST .../api/v1/services/aigc/text2image/image-synthesis`，Header `X-DashScope-Async: enable`，Body `{model:"wanx2.1-t2i-turbo", input:{prompt}, parameters:{size:"720*1280",n:1}}`
- 轮询：`GET .../api/v1/tasks/{task_id}` → `output.results[0].url`（24h）

### 5.4 百炼临时存储 — 上传本地图（免费，48h）⏳
- 取凭证：`GET .../api/v1/uploads?action=getPolicy&model=emo-detect-v1` → POST 文件到 OSS → `oss://...`
- 使用时 Header 加 `X-DashScope-OssResourceResolve: enable`
- 限制：文件**绑定 model**，48h，免费。风险：EMO 是否吃 `oss://` 待 M0 实测，不行退轻量图床

### 5.5 EMO — 对口型（两步异步）⏳
- Step1 `emo-detect-v1`：`POST .../api/v1/services/aigc/image2video/video-synthesis/`（异步），图片URL → `face_bbox`/`ext_bbox`（缓存）
- Step2 `emo-v1`：同 endpoint，Body `{model:"emo-v1", input:{image_url,audio_url,face_bbox,ext_bbox}, parameters:{style_level}}`
- 轮询 → `output.video_url`（对口型 mp4）

## 6. 功能详述

### 6.1 数字人对话
输入（文字/麦克风/快捷话题）→ 文字先秒回 → 语音合成 → 视频生成（异步，舞台显示「生成中」）→ 就绪自动播放口型同步。多轮保留最近 10 轮。兜底：LLM 失败用兜底话术；视频失败只播音频 + 静态形象，不卡死。

### 6.2 配置面板
浮层/侧栏，分组见 §8。改动即时生效（形象类需重新生成+检测，其余下一轮生效）。

### 6.3 形象管理
| 来源 | 公网 URL 怎么来 |
|---|---|
| 默认美女 | 文生图 https URL（启动缓存） |
| 预设库 | 提前生成缓存 |
| 提示词生成 | 文生图 https URL |
| 上传本地图 | 百炼临时存储 oss://（兜底图床） |

每次确定形象后调 `emo-detect-v1` 算 bbox → 缓存 `{imageUrl,faceBbox,extBbox}`。

### 6.4 语音输入（ASR）
浏览器 Web Speech API（zh-CN），按住麦克风说话 → 识别文字 → 自动发送。零依赖、免费、Chrome 最佳。

### 6.5 状态机
| 状态 | 触发 | 视觉 |
|---|---|---|
| idle 待机 | 默认 | 紫色光环、形象呼吸 |
| listen 聆听 | 按住麦克风 | 绿色光环 + 声波 |
| think 思考 | 等 LLM | 橙色光环 + 思考点 |
| generating 生成中 | 等 EMO 视频 | 紫色脉冲 + 进度 |
| speak 说话 | 播放视频 | 紫色高亮 + 对口型视频 |

## 9. 内容文案

**底座**：简体中文口语，像家人聊天，不列条；回复 1~2 句 40 字内；称呼亲切；不诊断病情、不碰敏感话题。

| 预设 | 风格 | 音色 |
|---|---|---|
| 温柔陪伴 | 轻慢软，先接情绪，多用「我在呢」 | 龙婉 |
| 知性 | 沉稳靠谱，给简单建议 | 龙华 |
| 活泼 | 热情有活力，多用「太好啦」 | 龙橙 |

开场白：「你来啦～我一直在这儿等你呢，今天还好吗？」
兜底：「我都听着呢，你慢慢说～」/「这会儿没听清，再说一遍好不好？」
快捷话题：今天过得怎么样 / 给我讲个开心的事 / 我有点想你了

## 11. 验收标准

1. 默认美女形象舞台正常显示。
2. 输入文字 → 对口型视频正常生成播放，口型与龙婉女声吻合。

4. 上传本地图能成功变公网 URL 用于 EMO（或图床兜底）。
5. 语音输入：按住说话 → 识别 → 回应。
6. 任一环节失败有兜底，不白屏不卡死。
7. 仅需一个 `DASHSCOPE_API_KEY`，`npm start` 即跑。
8. 视觉符合关怀岛屿设计系统。

## 12. 边界（不做什么）

- ❌ 不做实时流式数字人（EMO 异步，准实时）。丝滑实时是后续升级（DVH/Simli）。
- ❌ 不做声音克隆（用预置音色）。
- ❌ 不做多端/账号体系/双端（单页 demo，非完整 App）。
- ❌ 不在本地跑写实模型（GPU 专属）。
- ❌ 不强制「像本人」（默认预设美女；上传图需用户自负肖像授权）。
